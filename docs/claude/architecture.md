# Architettura

- `main.go`: app Wails v3, finestra frameless 1240x820, assets embed `frontend/dist`.
- `service.go`: unico servizio esposto al frontend (bindings in `frontend/bindings`, generati). Metodi: Installs, Profile, AddFolder/RemoveFolder, CachedNames/ResolveNames, ClientStatus, Apply, Backups, Restore, DeleteBackup, OpenBackupsFolder, Preview (sola lettura, vedi sotto), Accounts/SetAccountAlias/AccountPlan/IdentifyStart/IdentifyPoll/IdentifyStop (account, vedi sotto). Apply/Restore tornano `Result{ok, code}` (codici: client_running, bad_request, bad_backup, io, unknown_account), mai eccezioni per casi attesi.
- `internal/eve`: scoperta radici (Windows/macOS/Proton + `libraryfolders.vdf` + cartelle manuali), server -> `settings_*` -> `core_char_<digits>.dat`/`core_user_<digits>.dat`; rilevamento client (`/proc/*/cmdline` con `exefile.exe`, tasklist su Windows, ps su macOS).
- `internal/esi`: POST `universe/names` a lotti (404 sul lotto => split binario), cache `names.json`.
- `internal/backup`: zip + `manifest.json` in `<UserConfigDir>/capsuleers.settings/backups`, apply (char + opz. `UserCopy`), restore (valida che ogni percorso stia nella `profileDir` del manifest e abbia nome `core_*_<n>.dat`), tiene gli ultimi 20. Entry con `kind` char|user (`""` = char nei manifest vecchi), `charId`/`userId`.
- `internal/config`: `config.json` con le cartelle aggiunte a mano e `accounts` (vecchio, a mano), `accountLearned`, `accountGuided` (vedi Account).
- Frontend: Vue 3 + TS; stato globale in `src/store.ts` (reactive), 5 viste in `src/views/` (Profiles, Characters, Preview, Review, Backups), stringhe in `src/i18n.ts`.
- Frameless su Linux/Wayland: GTK3 con `decorated=FALSE` non annuncia CSD e KWin aggiunge la sua barra (doppia barra). `frameless_gtk3.go` (cgo, tag gtk3) crea la finestra `Hidden`, a runtime pronto imposta un titlebar GTK vuoto e nascosto (= CSD annunciato) con ombra/bordo/raggio azzerati e poi `Show()`; su X11 non fa nulla. Verificato su KDE 6.7 Wayland: frame == client. Drag/min/max/close sono quelli Wails invariati (click reali non iniettati nel test).
- Rilevamento client: conta solo processi con un argomento il cui nome file e' `exefile.exe` (non una semplice menzione in cmdline: shell, grep).

## Preview (sola lettura)
- `internal/marshal`: decoder puro Go, SOLO lettura, del formato CCP blue.marshal (opcodes da reverence `src/blue/marshal.c`). Mai un encoder nell'app: l'app copia file interi. Encoder di test in `internal/marshal/marshaltest` (fixture sintetiche; mai file reali nel repo).
- Formato: byte 0x7E, uint32 N slot condivisi, oggetti, poi tabella di N uint32 in coda. L'i-esimo oggetto con flag 0x40 (nell'ordine di incontro, contenitori contati all'apertura) occupa lo slot `tabella[i]-1`; REF n -> slot n-1. Stringhe/chiavi sono BUFFER (0x13); dict contati scrivono prima il valore poi la chiave; newobj/reduce = testa, elementi, MARK (0x2d), coppie chiave/valore, MARK. DBROW/BLUE/PICKLER non supportati (errore); STRINGR (tabella stringhe del client) diventa `<strtab:N>`; checksum 0x1c non verificato.
- Limiti: input 16 MB, profondita' 128, decoder iterativo, ogni lunghezza verificata contro i byte rimasti, `Decode` non va in panic (recover -> `ErrFormat`). `FuzzDecode` (`go test ./internal/marshal -fuzz FuzzDecode`). Corpus reale opzionale: `CAPSULEERS_CORPUS=<dir> go test ./internal/marshal ./internal/charsettings -run RealCorpus`.
- `internal/charsettings`: ogni valore di impostazione e' `(timestamp FILETIME, valore)`, in gruppi di primo livello (`windows`, `ui`, ...). Finestre: `windows/windowSizesAndPositions_<n>` = dict id -> `(left, top, width, height, schermoW, schermoH)`; ogni finestra ha le dimensioni dello schermo al salvataggio (UI scale 90% => 2133x1200, file misti normali). Il significato di `<n>` non e' documentato (nel corpus solo `_1`): si usa l'entry col timestamp piu' recente. Stato da `openWindows` (solo le aperte), `lockedWindows`, `collapsedWindows`, `compactWindows`, `minimizedWindows`; gruppi da `stacksWindows` (id -> stack padre, nil = libera), ordine tab da `preferredIdxInStack3`. Si mostrano solo le finestre di primo livello aperte; dialoghi transitori e stack numerici senza tab sono esclusi (`isTransient`, `numericRe`). Canali chat: `ui/chatchannels` (lista di `(suffisso, chiave, nome)`) piu' `chatchannel_*` aperti.
- Scala UI/schermo da `core_public__.yaml` (`LoadDisplay`, scanner a righe, no YAML). Etichette EN/IT in `labels.go`, id ignoti mostrati grezzi.
- `Service.Preview(profileDir, sourceId, lang)` torna `PreviewResult` (mai eccezioni; solo sorgente, nessun confronto): `source.error` `""|missing|unreadable`; un file non leggibile dà lo stato vuoto "can't read this file" e Apply non ne dipende. Vista: `PreviewView.vue`, raggiungibile da Characters e dalla rail.

## Account (core_user)
- `core_user_<userID>.dat` e' per ACCOUNT (overview/preset, `cmd/customCmds`, `ui`, tabgroups, suppress): condiviso da tutti i personaggi dell'account. ESI non da' char -> account. Niente euristiche su mtime: solo evidenze certe.
- Fonti (`accounts.Resolve`, un'evidenza = char, user, fonte, data): tier 3 = `launcher` (log del launcher, `/LauncherData=<base64>` = `product:tenant::userID:charID`) e `guided` (procedura IDENTIFICA), vince la piu' recente (trasferimenti di char); tier 2 = `launcher-esi` (righe `[esi] Fetching details for N` / `Fetched N character details {userId..}` accoppiate solo con un unico Fetching aperto della stessa N; char su piu' account scartato); tier 1 = `portrait` (`ui/pendingPortraitGeneration` del core_user) e `rift` (cluster `*_rift_backup_N` gap <= 1 s con 1 core_user e 1-3 core_char). Due account allo stesso livello/data = ignoto.
- Log: `accounts.LogsDir` risale a `AppData` dalla cartella profilo (Windows e prefix Proton) -> `Roaming/EVE Online/logs/eve-online-launcher-*.log`; macOS non supportato (ignoto). Parser difensivo (`launcherlog.go`): conserva SOLO userID/charID; le righe contengono token SSO che non vanno mai salvati, loggati o restituiti. Test con fixture sintetiche.
- Config: `accountLearned` (da log, persistito per sopravvivere alla rotazione ~2 settimane) e `accountGuided` (da IDENTIFICA), entrambi profileDir -> charID -> {userId, at, source}; `accounts` (vecchio, a mano) letto come `guided` senza data.
- IDENTIFICA (`identify.go`, `accounts/pairing.go`): `Service.IdentifyStart/Poll/Stop`. Snapshot degli mtime di core_char/core_user vivi (mai rift, sola lettura), poll 1 s; a modifiche ferme da 3 s (`Tracker`) `Pair(prev, cur)`: 1 solo core_user cambiato con >=1 core_char => char mappati a quell'account (salvati `guided`, nuovo baseline); >1 core_user => ambiguo, nulla; char senza user => nulla. Mappatura diversa da una salvata = aggiornata e segnalata (`remapped`). Si ferma da pannello chiuso/FINE, cambio vista o profilo.
- Vista Characters: personaggi raggruppati per account (alias modificabile nell'intestazione, default nomi di max 2 char + "+N") e gruppo finale "Da identificare" col pulsante IDENTIFICA (`IdentifyPanel.vue`).
- Copia: `accounts.MakePlan` in Go (dedup per account, salta target sullo stesso account della sorgente, `unknown` -> Apply rifiutato con `unknown_account`, messaggio che rimanda a launcher/IDENTIFICA). Lo zip include char e core_user prima di scrivere; stessa validazione/atomicita' dei char.
- Linux: `Linux.ApplicationID` = `app.capsuleers.settings`; all avvio `desktop_linux.go` scrive `~/.local/share/applications/app.capsuleers.settings.desktop` + icona hicolor (Exec = binario corrente), senza i quali Wayland mostra un'icona generica.
- Demo (solo screenshot README): `npm run demo` (porta 5199) sostituisce il service dei bindings con il mock `frontend/src/demo/service.ts` (dati inventati; alias in `vite.config.ts`, fuori dalla build). Shot con Playwright esterno al repo, host images.evetech.net bloccato (ritratti = iniziali), viewport 1240x820 @2x, in `docs/screenshots/`.
